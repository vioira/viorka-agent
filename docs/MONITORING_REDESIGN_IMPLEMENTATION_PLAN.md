## 1. 实施目标与执行约束

交付一套监控链路：管理 WSS 常驻；无实时订阅按独立 C（1–60 秒、默认 30 秒）采集并按 R POST；有订阅按 W 采集并经 WSS 上报；固定 30 秒历史聚合；TCP/UDP 保持现有 inuse；历史列式展开并每周轮换；本地月流量独立恢复。

当前是开发测试环境：不要求兼容或迁移现有历史数据表，不导入旧历史、不保留旧 60 秒桶查询层，不实施生产历史升级/回退演练。直接建设新表和新数据链路。协议兼容、新表自身的重启恢复及非监控数据保护仍在范围内。

“列式展开”仅指关系表中每个指标有独立字段，不是引入列式数据库。数据库继续使用现有 SQLite；前端继续使用现有 SSE，不增加浏览器直连 Agent。

执行约束：

1. 每个仓库开始修改前重新检查 git status、适用 AGENTS.md、当前依赖和协议版本，保留已有用户改动。
2. 本计划按职责分工，不表示已授权启动多个子代理或同时修改共享文件；默认按依赖顺序执行。
3. 先修改 Panel 权威协议，再同步 Agent 模型，不手改 models.gen.go；REST/OpenAPI 使用现有生成链。
4. 每阶段提供可复现结果，不以占位 handler、fake 成功或 UI 声称已支持代替实现。
5. 不触碰真实代理服务、不清空生产数据库、不自动发布、不借本次工作执行安装/卸载/接管。
6. 纯文档阶段到此为止；下面是后续实施者任务，不是本次已经执行的动作。

## 4. P1：存储和固定 30 秒聚合

7. 维持单实例聚合和有限内存；设置全局字节预算、节点/设备上限、过载拒绝和数据库失败重试/过期丢失诊断。

涉及 Panel：`internal/httpapi/router.go`、新指标上传 handler/DTO、`internal/gateway/gateway.go`、`internal/monitoring/`、`internal/auth/`、`internal/storage/agents.go`、OpenAPI。

任务：

1. 抽出小型公共接收服务，HTTP/WSS 共用身份关联、组校验、去重、最新快照和聚合器。
2. 注册 Agent 专用 POST 路由，拒绝 Web Cookie 身份、URL 凭证、跨节点 body、未知内容类型及超限 body。
3. 复用已实现的短期会话认证，定义过期与吊销的安全错误码；不通过新会话登录产生持续 WSS 踢线。
4. 不要求 POST 时管理 WSS 已在线；但能力/协议和身份必须有效，不能仅凭 node_id 上传。
5. 全批校验完成后再改变接收状态，返回 batch_id 对应接收回执；重复只计 duplicate，不当错误重试。
6. WSS 增加相同回执语义，保留单 writer 和控制消息优先级；指标背压不能静默丢弃任务结果。
7. 新鲜度独立于管理 online：POST 成功可显示指标新鲜，但不把节点标成任务可达。
8. 更新最新指标和历史 DTO：包含来源、组时间、实际节奏、数据质量、当前模式；不要在产品 UI 暴露无助决策的内部 token/队列实现。
9. 认证/节点吊销影响两个入口；429 带可解析 Retry-After，错误文本不泄漏内部信息。

## 6. P3：Agent 采集拆分和月流量

涉及 Agent：`internal/collector/metrics.go`、`host_metrics.go`、`filesystems.go`、`inventory.go`、`internal/config/local.go`、`internal/state/` 及测试。

任务：

1. 将 fast/full/public_ip 拆成职责清楚的采集入口和类型化快照，保留共享计数基线的单一所有者。
2. fast 只读 CPU、内存、Swap、网络、TCP/UDP 和运行时长；full 负责容量、负载、进程及磁盘 I/O。
3. TCP/UDP 原解析器保持 inuse、IPv4/IPv6、缺 sockstat6 和失败语义；不引入 tcp* 扫描。
4. 公网 IP 从 OS 信息刷新中拆出，复用固定探测源与现有 TLS/超时，周期变为 600 秒。
5. 磁盘保留 mountinfo、白名单和去重；I/O 扩展完成次数、耗时、忙碌时间差值，按设备报告。
6. 实现接口过滤和本地配置验证、filter_revision、逐接口差值；不要将虚拟接口规则当作计费准确性保证。
7. 增加独立月累计状态和 traffic.dat 原子快照，绑定身份、boot_id、接口身份和统计周期；保存基线与累计值必须原子一致。
8. 处理月份切换、跨月停机、接口替换、规则变化、损坏/写失败，不让月流量失败中断其他管理功能。
9. 保留受限读大小、设备数、枚举数和超时；确认慢完整任务不占用 fast 和网络 writer。
10. 新指标与已有协议适配分开；旧 Panel 收到的还是旧协议结构/允许字段。

交付物：采集器、月账本、本地配置示例、procfs fixture 单测、Linux 实采集证据。

阶段门槛：首次/倒退/失败恢复无假零和尖峰；full/IP 快照复用不改时间；Agent 重启后月累计无重复增量；未知情况报告退化；无新 root 要求或 shell 命令。

## 7. P4：Agent 调度、会话和故障状态机

涉及 Agent：`internal/connection/client.go`、`sampling.go`、`settings.go`，可按职责新增小文件，例如会话提供者、指标 POST 和模式调度；避免建立泛化 manager 包。

任务：

1. 实现进程级单会话协调器，POST/WSS 共用 token 和 expiry；challenge/refresh 串行，更新凭证只触发受控重连。
2. 实现独立管理连接状态、指标模式和熔断状态；仅实时模式暂停 POST，管理 WSS 在线不暂停。
3. 支持 C/R/W 规则、采集后发送、设置动态重排、run_id/分组序号以及缓存观测身份不变。HTTP 修改 R 不重排 fast，C>R 的 POST 复用原快照不加采；实时修改 C 仅保存，退出后生效。
4. 实现 300 样本/1 MiB 待发送窗口、在途所有权、按 64 KiB 拆 WSS 帧；约束复制缓冲和 worker 数。
5. 模式切换串行：在途 POST 最多等待其 deadline；未尝试窗口转移，失败窗口清空；不能并行启两个无限发送循环。
6. 实现租约启用/停用/续期回执、过期退出、会话换代拒绝旧命令、Agent 重启不恢复旧实时租约。
7. 实现最新快照兜底、R 最小尝试间隔、120 秒冷却、共享拒绝阶梯和单探测半开；控制/身份错误与指标过载分开。
8. 管理连接沿用基础 1→30 秒加抖动；真实吊销和 TLS 错误不进入“换 POST 再试”的旁路。
9. 指标 ACK 超时释放窗口并退回 HTTP；收到迟到 ACK 不把更高代次状态倒退，也不清除新的失败计数。
10. 有界关闭采集/HTTP/WSS/账本任务，不停止代理进程；状态目录有界，不新增指标历史落盘。

交付物：状态机、HTTP 客户端、会话协调、可注入时钟和抖动源的测试、背压与关闭测试。

阶段门槛：POST 与 WSS 不互踢；冷却期间无忙循环和历史积压；模式切换保留真实速率基线；所有测试等待有界，不能依靠长时间 sleep 偶然通过。

## 8. P5：订阅生命周期和前端

涉及 Panel：`internal/httpapi/metric_events.go`、`internal/realtime/`、Gateway 的需求通知/单 writer；Web：`use-live-metrics.ts`、`NodeSettings.tsx`、实时和历史指标组件、API 类型。

任务：

1. 在实际 SSE 节点集合确定和权限校验成功后注册需求；处理详情 scope 与列表 scope，不使用全局事件订阅者数代替。
2. 节点级引用计数，首订阅启动、末订阅 15 秒宽限退出；多个页面只产生一份实时流。
3. 节点删除、分页作用域变化、登录失效、权限变化、SSE 取消/写失败都释放需求；Panel 重启不恢复幽灵订阅。
4. 单管理 writer 发送 demand，90 秒租约每 30 秒续期；容量为 1 的唤醒可合并需求，但不能丢掉最终 desired 状态。
5. 展示 pending/realtime/http/degraded 和快/慢组更新时间；SSE 初始快照成功不等于 Agent 已确认实时模式。
6. 设置表单显示“采集间隔”“HTTP 上报间隔”“WSS 实时上报间隔”：C 范围 1–60、默认 30，不允许 0，不与 R 联动；说明实时覆盖 C、历史固定 30 秒。
7. 保留前端隐藏页面断开 SSE 的机制，切回后恢复；列表也按实际订阅节点产生需求，不能触发所有未加载节点。
8. 统计值文案准确：TCP inuse、UDP socket、采样峰值、样本均值、UTC 月流量；缺值不显示 0，慢指标不假装秒级刷新。
9. 历史只读新表，底层固定 30 秒；没有对应组观测时该组显示缺口，slow-only 桶不补 fast 值；不做旧 60 秒点兼容。
10. 前端沿用现有组件、错误反馈、权限处理和 API 校验，不借本次变更做无关重构。

交付物：订阅管理、需求控制、表单和图表状态、前端单测/集成测试、UI 手工验收记录。

阶段门槛：开两页关一页仍实时，关最后页延迟恢复 HTTP；浏览器崩溃最终恢复；管理任务不受页面开关影响；HTTP 新鲜数据不因管理离线被伪装陈旧。

## 9. 必须验收的测试矩阵

使用可注入时钟验证长周期，不在单元测试中真的等待 10 分钟。关键 I/O、新库初始化和周轮换仍使用真实进程、TLS 和 SQLite 验证。

| ID | 场景 | 必须结果 |
| --- | --- | --- |
| T01 | HTTP 默认 C=30/R=60 | fast 每 30 秒、full/POST 每 60 秒；一次 POST 通常约 2 个 fast 点，分别按真实时间归桶 |
| T02 | HTTP C=2/R=60 | 约 30 fast 点一个 POST，按真实时间生成约两个基础桶 |
| T03 | realtime C=60/W=1 | fast 每 1 秒，C 被忽略；POST 停止，full 仍按 R |
| T04 | realtime W=2、full R=60 | full/IP 缓存不被重复计数、时间不刷新 |
| T05 | 采集慢于 deadline/设备探测阻塞 | 无采集任务积压；心跳/设置处理继续；可取消边界和实际限制如实报告 |
| T06 | 首次 CPU/网卡/I/O、计数回退、错误恢复 | 不补零、不负速率、不异常尖峰，重新建立有效基线 |
| T07 | TCP/UDP fixture、缺 IPv6 文件、监听/TIME_WAIT | 与当前 inuse 语义一致，不改为 ESTABLISHED 数量 |
| T08 | 多文件系统、bind/Btrfs、虚拟/网络挂载 | 去重正确；不访问不受支持远程挂载；失败不报部分合计正常 |
| T09 | IOPS/Await/Util 固定计数 fixture | 公式、单位正确；无完成次数时 await=NULL；设备层不重复相加 |
| T10 | 默认过滤、显式包含/排除、规则变化 | 过滤顺序和 revision 正确；隧道可明确纳入；无 silent mixed semantics |
| T11 | traffic.dat 保存→进程重启→同主机计数增加 | 累计只加新增差值，基线与累计不发生双记 |

### 11.4 回退规则

| 故障 | 优先处理 |
| --- | --- |
| 实时订阅或模式切换异常 | 关闭新实时需求，Agent 租约到期恢复 HTTP；若自动模式整体异常则重新协商旧 WSS 路径 |
| POST 接口异常 | 对支持旧模式的节点切回已确认旧 WSS 指标路径，不切断管理能力 |
